# v1.0.7

- Keep BAM's selected output independent of the macOS default. Starting BAM or changing the system default no longer replaces the saved BAM selection.
- Keep a missing or ambiguous BAM output unavailable instead of silently switching to the system default. Unambiguous USB re-enumeration still reconnects the selected device.
- Require volume/mute protection only for current and previously used BAM listening outputs. A separate capture device without those controls no longer blocks startup.
- Preserve the user's selection after failed routing and retain live resources when no output can be safely protected.

No device is hardcoded, and BAM does not change the macOS default. If both selections use the same physical device, its hardware controls remain shared. Original audio may resume on the macOS output when taps stop reading; independent selection is not a guarantee of silence on every output.

Verified with separate macOS/BAM devices, automated tests, Release build and static analysis. See [implementation and verification](../diagnostics/2026-09-06-decoupled-output-proposal.md). Acoustic peak containment remains unmeasured.
