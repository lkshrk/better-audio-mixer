# v1.0.6

- Keep configured source taps and the shared audio renderer alive as applications start and exit, preserving gains and limiter state during membership updates.
- Confirm hardware mute/volume changes and valid callback progress before restoring playback. Failed or uncertain writes prevent automatic restoration.
- Validate complete output stream layouts, including stereo devices with two mono streams.
- Fix Stream Deck master adjustments wrapping a cached zero level to 100%. Master adjustments now use the app's current level and clamp at the endpoints.
- Add command timing and volume-origin diagnostics to distinguish UI/control requests from restoration.

Validation includes package/App tests, Release build/static analysis, a 90-second low-volume playback check and three configured audio-source launch/exit cycles with no aggregate rebuilds or reported failures. Hardware testing used approximately 12% volume on one output device. Protection of the first audio samples at maximum hardware gain and acoustic latency/continuity have not been measured; this release does not certify those properties. See [trial results](../diagnostics/2026-09-06-volume-origin-followup.md).

If a hardware write is accepted but cannot be confirmed, further volume changes or unmuting are blocked and mute is attempted. Recovery may require reconnecting the device. Download the app and Stream Deck plugin from this release, or install the app with `brew upgrade --cask lkshrk/tap/bam`.
